# 01 需求（Requirements）

> 軟體開發五個週期的第 1 階段。本文件說明「要做什麼」，不說「怎麼做」。
> 基準：**2026-11-11 實驗室成品**；2026-11-17 依原始碼、建置報告、重新模擬及作者驗收回報更新。

## 1.1 目的與範圍

在 EGO-XZ7 開發板（Zynq XC7Z020-CLG484）的 PL 端，用 VHDL 實作雙人「乒乓球 LED」遊戲：
一排 LED 代表球的位置，兩位玩家各用一個按鍵回擊。本版本為**單板版**。

## 1.2 需求來源

課堂白板（老師手寫）。下表是我對白板內容的轉錄與判讀，**被老師身體擋住或看不清的部分已標註**。

| 白板內容 | 判讀 | 本專案處理 |
|---|---|---|
| 乒乓 LED：player1 ─ SW1 ─ 一排 LED ─ SW2 ─ player2 | 兩位玩家，中間一排 LED（照片上判讀為 8 顆） | 採用（FR-01、FR-02） |
| ① rst：向右移 | reset 後球往右（player2 方向）移動 | 部分採用：改為「發球後才移動」，見 1.7 |
| ② 到最左／右終端按 SW 回擊，變成反向移動 | 球到端點時按鍵回擊，球反向 | 採用（FR-04） |
| ③ 回擊失敗：太早按 SW → 對方 +1；「太晚」被擋住 | 太早、太晚都算失分 | 採用（FR-05、FR-06） |
| ④ 每回合顯示分數 | 每回合結束要顯示分數 | 採用（FR-08） |
| 「……達人（Block RAM 存音樂檔）」、「pseudo」 | 文字部分被遮住；「pseudo」推測為偽隨機（**推論**） | 偽隨機用於變速（FR-09）；音樂不在本次範圍 |
| 下一階段：① VGA 版本 ② 2 個或以上板子互打 | 後續作業方向 | **本專案範圍外** |

## 1.3 名詞定義

| 名詞 | 定義 |
|---|---|
| player1 / player2 | 左邊玩家（BTNL）／右邊玩家（BTNR）。LED0 是 player1 端，LED7 是 player2 端 |
| 發球者 | 剛得分的玩家；開機後預設為 player1 |
| 接球者 | 球正在飛向的那一位玩家 |
| 端點 LED | 接球者那一端的 LED（LED0 或 LED7） |
| 一步 | 球移動一格 LED 所需的時間 |
| 回擊窗口 | 球停在端點 LED 的那一步時間 |

## 1.4 功能需求

| ID | 需求 | 驗收方式 |
|---|---|---|
| FR-01 | 兩位玩家：player1 用 BTNL、player2 用 BTNR | 上板操作 |
| FR-02 | 等待發球、飛行與回擊窗口時，用 LED0–LED7 顯示球的位置，同一時間只亮一顆；得分與獲勝畫面依 FR-07、FR-08 | 模擬、上板 |
| FR-03 | reset 後 player1 先發球。之後由得分者發球，發球者可隨時按自己的鍵開球；發球前只有發球者的鍵有效 | T1、T2、T5 |
| FR-04 | 球到端點 LED 時，接球者在回擊窗口內按鍵 = 有效回擊，球反向 | T2 |
| FR-05 | **太晚**：回擊窗口結束仍未按鍵，接球者失分，對手 +1 | T3 |
| FR-06 | **太早**：發球後，球飛向接球者、尚未到達端點時，接球者按鍵，接球者失分，對手 +1。球飛離某玩家時，該玩家按鍵一律忽略。發球前不判定 | T4、T8 |
| FR-07 | 先得 `WIN_SCORE` 分者獲勝（預設 5，可設定）。遊戲進入結束狀態：**勝方那半邊四顆 LED 恆亮**（player1 贏 = LED0–LED3，player2 贏 = LED4–LED7），不顯示二進位，只能靠 reset 離開 | T6、T9 |
| FR-08 | 每回合結束顯示分數：得分者那半邊以 **4 位元二進位**顯示該方分數（player1：LED0 = 最高位元 … LED3 = 最低位元；player2：LED4 = 最高位元 … LED7 = 最低位元），另一半邊熄滅。顯示時間 `SHOW_TIME` 的前半段亮、後半段熄滅（**一個明暗週期**，不是依分數閃幾次），之後回到等待發球；若已達獲勝分數，則進入 FR-07 的獲勝畫面 | T3、T4、T6、T7 |
| FR-09 | SW0 = 0 為勻速；SW0 = 1 為隨機變速。變速時，每次有效回擊（含發球）重新取一次亂數，決定接下來這一趟的每步時間，飛行途中不變 | T7 |
| FR-10 | SW7 往下 = reset 並暫停全部動作；往上 = 開始運作 | T1、T8、上板 |
| FR-11 | 所有外部輸入（按鍵、開關）都要同步、去彈跳，按鍵每次按下只產生一次事件 | B1～B6 按鍵整理模擬、設計審查 |

## 1.5 非功能需求

| ID | 需求 |
|---|---|
| NFR-01 | 同步設計，只使用單一 100 MHz clock，不產生衍生 clock |
| NFR-02 | 每個 signal 只由一個 process（或一條並行指定）驅動，方便除錯 |
| NFR-03 | 時間、分數、亂數 bit 數等參數用 `generic`，不寫死在程式裡，不留技術債 |
| NFR-04 | 提供自我檢查的 testbench（失敗會 assert，通過會印訊息） |
| NFR-05 | 設計要能維持原有結構，往後擴充（雙板互打、VGA）時不必推翻 |

## 1.6 範圍外

- 音樂播放、Block RAM
- 兩塊以上板子互打
- VGA 顯示
- 七段顯示器（**已棄用**，見 1.8 變更紀錄）

## 1.7 需求決策紀錄

| 問題 | 決定 | 說明 |
|---|---|---|
| LED 數量 | 8 顆（板上 LED0–LED7） | 手冊表 15 |
| 回擊用開關還是按鍵 | **按鍵** BTNL／BTNR | 白板寫 SW，但板上 SW 是撥動開關，不適合當回擊鍵；BTNL／BTNR 剛好在左右兩側 |
| 「太晚」怎麼定義 | 端點那一步時間結束沒按 | 若定義為「LED 亮到端點」就會讓合法回擊不存在 |
| 「太早」怎麼定義 | 選項 A：球飛向你、尚未到端點時按 = 太早；球飛離你時按 = 忽略 | 另兩個選項：B（發球後只要球不在你端點按就算太早，過於嚴格）、C（只有最後 N 格才算太早，多一個參數）。選 A 以免剛回擊完又多按一下就被罰 |
| 誰先發球 | player1；之後得分者發球，隨時可按 | |
| 勝利條件 | 先得 5 分，可調 | 以 `WIN_SCORE` 表示 |
| 變速 | 開關只有「勻速／變速」兩種；變速由偽隨機決定；每次回擊更新一次 | 曾討論「用計數器 MSB 當亂數」：MSB 只是規律方波，不是亂數，改用 LFSR（見 03 設計） |
| 本次範圍 | 單板打球；音樂、雙板留待後續 | |
| 分數怎麼顯示 | 最終：**LED 二進位**，七段完全棄用 | 七段實測無法點亮（含獨立測試設計），使用者決定不再追查；見 05 驗證 |
| 5 分獲勝的畫面 | 勝方半邊四顆 LED 恆亮，**不是**長亮二進位 0101 | 第 5 分仍會先走一次「二進位 0101 → 熄滅」，再進入恆亮 |

## 1.8 需求變更紀錄

| 版本 | 變更 | 原因 |
|---|---|---|
| v1.0 | 初版：分數由**七段顯示**，顯示最近得分者的分數，得分側 4 顆 LED 亮 | 手冊記載板上有七段 |
| v1.1 | 分數改為 LED 長條（中間版本，已被 v1.2 取代） | 七段無反應 |
| **v1.2** | 分數改為 **4 位元二進位**；勝利改為勝方四顆 LED 恆亮；當時 GitHub 整理版將 `WIN_SCORE` 上限擴為 15；實驗室成品實際為 9；移除 `seg` 埠與七段腳位約束 | 使用者最終需求。七段不論極性與獨立測試設計都無法點亮，決定棄用 |

## 1.9 假設與待確認

- 白板上被遮住的規則，以上述判讀為準；若老師實際規則不同，需更新本文件。
- 板子實際按鍵位置（BTNL 是否真的在中間那排最左）依使用者回報，詳見 `05-verification.md`。
- 二進位顯示的位元順序（LED0 為 player1 最高位元、LED4 為 player2 最高位元）來自使用者的最終需求，本專案照做。

## 1.10 成品核對與驗收

實驗室原始碼的 WIN_SCORE 範圍為 1..9，預設仍為 5；本次依成品還原範圍。4-bit 顯示本身可表示 15，但不代表程式開放 15 分設定。

作者於 2026-11-17 回報：上週在實驗室完成，已由老師檢查、功能正常。此為整體實機驗收回報，未提供逐項簽核或影片。新增模擬與實驗室建置證據見 [第 5 階段](05-verification.md)。

本成品頂層只有 clk、rst_n、mode_sw、btn_l、btn_r、led，沒有獨立外接手把介面，也沒有 seg 輸出。player1／player2 是邏輯角色；實板 LED 為直排，以 LED 編號與二進位位元表為準，避免用畫面左右推定實際上下。
