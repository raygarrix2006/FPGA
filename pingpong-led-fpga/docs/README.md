# 軟體開發五階段總覽

本專案用五階段組織 FPGA 開發：需求 → 分析 → 設計 → 程式實作 → 驗證。這是文件與工作流程，並不表示硬體驗證已完成。

| 階段 | 要回答的問題 | 主要產出 | 交付檢查點 |
|---|---|---|---|
| 1. [需求](01-requirements.md) | 遊戲要做什麼？怎樣算符合要求？ | FR-01～FR-11、NFR、範圍、規則與變更 | 規則與驗收方式能對應 |
| 2. [分析](02-analysis.md) | 硬體、時間、事件、風險如何影響需求？ | 板卡資源、事件條件、時序及風險 | 分清手冊記載、作者回報與推論 |
| 3. [設計](03-design.md) | 模組與訊號如何合作？ | 架構圖、FSM、參數、腳位與 LED 對照 | 設計可追到 RTL 的 process／訊號 |
| 4. [程式實作](04-implementation.md) | 如何編寫及建立工程？ | VHDL、XDC、Tcl 與版本差異 | 現行來源和歷史來源分開 |
| 5. [驗證](05-verification.md) | 怎麼證明符合需求？還缺什麼？ | T1～T7、歷史波形、上板清單與失敗紀錄 | 未執行項目不可標成通過 |

[需求→設計→程式→測試追溯](traceability.md)把這五階段串在一起。[狀態與待辦](project-status.md)列出下一步；[操作說明](user-guide.md)供使用板子的人閱讀。

需求改變時，先更新第 1 階段與變更紀錄，再檢查分析、設計、程式和測試是否需要一起更新。
